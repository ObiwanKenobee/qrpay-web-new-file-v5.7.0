# ADR 0007: Private dispute evidence and platform review

- **Status:** Proposed implementation
- **Date:** 2026-11-13
- **Scope:** Evidence attached to a Sanctum Scan exchange dispute

## Context

Milestone 006 established participant-only dispute records and append-only statements. Those statements provide context but do not let participants attach documents or let a reviewer record a separate assessment of a submitted artifact.

The next increment needs a bounded evidence workflow without turning uploaded files into public URLs, treating a filename or payment reference as proof, or rewriting a participant's original submission.

## Decision

### Private evidence submission

Either authenticated participant may attach evidence while the dispute is `open`. Each evidence record stores:

- Evidence type and optional participant caption.
- Sanitized display filename, detected MIME type and byte size.
- SHA-256 digest of the uploaded bytes.
- Private storage disk and generated storage key.
- Authenticated submitting guard and participant ID.
- Submission timestamp.

Only PDF, JPEG and PNG files up to 10 MiB are accepted. Storage keys are generated by the application; client filenames never determine the storage path. Evidence uses the existing `local` filesystem disk, whose root is `storage/app`, not the public storage disk. No public URL or direct object-storage URL is returned.

Evidence metadata is immutable through its application model. Files are kept on a private disk, have no participant write or delete route, and are checked against their recorded digest before review or download. The same SHA-256 digest cannot be attached to the same dispute twice.

### Participant access

Evidence listing and download require the authenticated exchange participant. The controller first scopes the exchange to the authenticated buyer or merchant and then scopes the evidence to that exchange's dispute. Downloads are streamed as attachments with `private, no-store` and `nosniff` headers.

Before a download or review, the service recomputes the file digest. Missing files and hash mismatches fail closed.

### Platform review

An authenticated administrator protected by the existing admin role-permission and two-factor middleware can list pending evidence, download the private file and submit one review decision per evidence record.

Each review is a separate immutable record containing:

- `verified`, `rejected` or `unable_to_verify` decision.
- Review method (`document_review`, `source_cross_check`, `field_inspection` or `other`).
- Required written review summary.
- Administrator ID and review timestamp.
- SHA-256 digest of the exact file reviewed.

The reviewer must pass the file-integrity check before a decision is recorded. An exchange event links the review action, reviewer identity, evidence ID and digest to the existing event timeline.

## Trust and privacy boundaries

- A submitted file is participant-provided material, not verified truth.
- The platform review is an internal administrator review, not independent third-party certification or legal adjudication.
- A `verified` status means a platform reviewer recorded a positive conclusion using the declared review method. It does not prove the underlying goods were delivered, the goods meet a quality standard, or a payment settled.
- No automated payment-provider integration, M-Pesa confirmation, settlement reconciliation, refund or chargeback is introduced.
- Evidence files are not exposed on the public QR scan page or through unauthenticated routes.
- Review decisions and original submissions cannot be edited or deleted through their Eloquent models.
- One review is allowed per evidence item in this slice; appeals, re-review and multi-reviewer quorum are deferred.
- Evidence submission does not change the dispute state, exchange state, wallet balances, transaction rows or payment evidence.
- File retention, malware scanning, external object storage and customer-configurable retention policy require production hardening before sensitive real-world deployment.

## Consequences

### Positive

- Adds a private evidence trail alongside party statements.
- Preserves a content hash so reviewers and participants can detect storage alteration.
- Separates an immutable upload from its separate review decision.
- Records who reviewed what, how and when, without overwriting the submitted artifact.

### Trade-offs and non-goals

- Local private storage is appropriate for the reference implementation but requires durable protected storage, backup and malware scanning before production.
- The first implementation restricts file type and size rather than supporting arbitrary attachments.
- Platform administrator review is an internal control. External independent verifiers and institutional evidence integrations require separate trust, identity, governance and authorization design.
